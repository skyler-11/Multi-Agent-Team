# Persistence (database-agnostic) + Migrations

Goal: data access that works on SQLite, Postgres, or MySQL by changing config — not code — and that matches the repo's async/sync style. All ORM access stays in the Repository layer.

## 1 — One setting drives the dialect

```python
# config.py
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    database_url: str = "sqlite+aiosqlite:///./app.db"  # async sqlite default
    class Config:
        env_file = ".env"

settings = Settings()
```

Swapping databases is now a `DATABASE_URL` change:
- SQLite (async): `sqlite+aiosqlite:///./app.db`
- SQLite (sync): `sqlite:///./app.db`
- Postgres (async): `postgresql+asyncpg://user:pass@host/db`
- Postgres (sync): `postgresql+psycopg://user:pass@host/db`

## 2 — Engine + session: match the repo's style

**Async (SQLAlchemy 2.0):**

```python
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

engine = create_async_engine(settings.database_url)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)

async def get_session() -> AsyncSession:        # FastAPI dependency
    async with SessionLocal() as session:
        yield session
```

**Sync:**

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, Session

engine = create_engine(settings.database_url)
SessionLocal = sessionmaker(engine, expire_on_commit=False)

def get_session() -> Session:                   # FastAPI dependency
    with SessionLocal() as session:
        yield session
```

**Rule:** sessions are injected via `Depends(get_session)` into the repository layer only. Never a module-global session; never open a session inside a service or router.

## 3 — Models stay portable

Use SQLAlchemy 2.0 typed models and avoid dialect-specific column types unless guarded:

```python
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column
from datetime import datetime

class Base(DeclarativeBase): ...

class Request(Base):
    __tablename__ = "requests"
    id: Mapped[int] = mapped_column(primary_key=True)
    item: Mapped[str]
    quantity: Mapped[int]
    created_at: Mapped[datetime] = mapped_column(default=datetime.utcnow)
```

Prefer portable types (`str`, `int`, `bool`, `datetime`, `JSON`). If you need a Postgres-only type (`JSONB`, `ARRAY`, native enum), isolate it and note the lost portability in the handoff.

## 4 — Dialect gotchas to guard

| Concern | SQLite | Postgres |
|--------|--------|----------|
| Foreign keys | OFF by default — enable per connection (`PRAGMA foreign_keys=ON`) | On |
| Schema changes | No native `ALTER` for many ops — Alembic uses batch mode | Full `ALTER` |
| Concurrency | Single-writer; fine for dev/portfolio | Real concurrency |
| Case-insensitive search | `LIKE` is case-insensitive for ASCII | `ILIKE` |

Don't write raw SQL that assumes one dialect. Let the ORM emit it.

## 5 — Alembic migrations

Migrations are how the schema changes safely once data exists. Set it up once:

```bash
alembic init alembic
```

Point Alembic at your models and URL:
- In `alembic/env.py`, set `target_metadata = Base.metadata` and read the URL from your settings (don't duplicate it in `alembic.ini`).
- For **SQLite**, enable batch mode so `ALTER`-heavy migrations work: pass `render_as_batch=True` to `context.configure(...)`.
- For **async** engines, run migrations through a sync engine (Alembic drives DDL synchronously) — use a sync driver URL for Alembic even if the app is async.

Workflow:

```bash
alembic revision --autogenerate -m "add status column"   # generate from model diff
# REVIEW the generated script — autogenerate misses renames, server defaults, type changes
alembic upgrade head                                       # apply
alembic downgrade -1                                       # roll back one
```

**Always read the autogenerated script before applying.** Autogenerate compares model metadata to the DB and guesses; it routinely misclassifies column renames as drop+add (data loss) and misses constraint/default changes. Edit the script to be correct and reversible.

## Repository shape (where all of this is used)

```python
class RequestRepository:
    def __init__(self, session): self.session = session
    async def list(self): ...      # the ONLY place queries live
    async def create(self, data): ...
```

Services depend on the repository, not on the session or the ORM directly — so a DB swap or query rewrite never escapes this layer.
